# Per-address Primary-Sale Cap — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prevent one address from buying every ticket in a primary-sale batch by enforcing a per-event, configurable cap in the smart contract and surfacing it clearly in the UI.

**Architecture:** Store `maxPerBuyer` on each `EventDetails`, add a `primaryBought[eventId][buyer]` counter, and gate the cap in `resaleTransfer` only when `seller == owner()` (the organizer). Frontend reads both values through the existing `useTicketBoard` batch and preemptively disables the Buy button when the connected wallet is at its limit; the raw revert is remapped to a friendly sentence.

**Tech Stack:** Solidity 0.8.24 + OpenZeppelin 5 (contract), Hardhat + Chai (tests), React 19 + wagmi/viem + MUI 9 (frontend).

**Spec:** [`docs/superpowers/specs/2026-08-05-primary-sale-cap-design.md`](../specs/2026-08-05-primary-sale-cap-design.md)

## Global Constraints

- **Primary-sale definition:** `seller == owner()`. Comment the choice in the contract; the trade-off (organizer buy-back + resell also counts as primary) is documented in the spec.
- **`maxPerBuyer == 0` means unlimited.** No other sentinel.
- **Exact revert string:** `"Primary purchase limit reached for this event"`. The frontend depends on the literal wording.
- **No backwards-compat shims.** `mintAndList` gains a required `maxPerBuyer` argument; every caller is updated.
- **No frontend test framework added.** Frontend changes are verified manually per the steps in each task.
- **ABI export is regenerated by `contracts/scripts/deploy.js`** — after any contract change, the deploy script must run so `frontend/src/contracts/TicketNFT.json` picks up the new signature.

        // Primary sale = seller is the organizer. Secondary sales stay
        // uncapped: the face-value ceiling already prevents scalping there,
        // and capping them would block legitimate resale. The "seller ==
        // owner()" choice is documented in the spec; the trade-off is that
        // if the organizer buys back and re-sells, that re-sale counts as

        if (seller == owner()) {
            uint256 eventId = tickets[tokenId].eventId;
            uint256 cap = eventDetails[eventId].maxPerBuyer;
            if (cap != 0) {
                require(

                    "Primary purchase limit reached for this event"
                );
            }
            primaryBought[eventId][msg.sender] += 1;
        }

- [ ] **Step 1: Extend `readableError` to intercept the cap revert**

Update `frontend/src/lib/format.ts`:

```ts
const REVERT_MESSAGES: Record<string, string> = {
  'Primary purchase limit reached for this event':
    "You've hit this event's per-wallet purchase limit.",
};

export function readableError(error: unknown): string {
  if (error && typeof error === 'object' && 'shortMessage' in error) {
    const short = (error as { shortMessage?: unknown }).shortMessage;
    if (typeof short === 'string' && short.length > 0) {
      for (const [needle, replacement] of Object.entries(REVERT_MESSAGES)) {
        if (short.includes(needle)) return replacement;
      }
      return short;
    }
  }
  if (error instanceof Error) return error.message.split('\n')[0];
  return 'Something went wrong';
}
```

`shortMessage` from viem is usually something like `The contract function "resaleTransfer" reverted with the following reason: Primary purchase limit reached for this event`, so `.includes(needle)` matches without depending on exact wrapper text.
